# Sentinel Rosetta

Offline English-Chinese neural translation for air-gapped networks. A command-line tool, an HTTP API and a Streamlit page share one use case. Translation runs Helsinki-NLP Opus-MT models through CTranslate2 on a CPU. Military terminology comes from fine-tuned weights, not from a runtime glossary. A separate command fine-tunes a model on sentence pairs that a teacher LLM wrote.

## Getting Started

Requires Python 3.9.6, the version the project is developed and tested on (`pyproject.toml` accepts any 3.9.x).

```bash
python3.9 -m venv .venv
source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

Download the two Opus-MT models and convert them to CTranslate2 int8 once. `torch` is needed only for this step; on Linux or Windows add `--extra-index-url https://download.pytorch.org/whl/cpu` for the CPU build.

```bash
pip install torch
python scripts/download_models.py
```

The script writes `models/opus-mt-<pair>/` (tokenizer) and `models/opus-mt-<pair>-ct2/` (weights) and skips directories that already exist. `torch` can be uninstalled afterwards.

## Usage

Run from the project root with the virtual environment activated; the code resolves `models/` and `data/` relative to the working directory.

```bash
sentinel translate -s en -t zh "Their commercial space sector features partially state-owned enterprises."
sentinel translate -s zh -t en "其商業太空部門，包括遙感探測、發射與通信服務，具有部分國有的企業"

uvicorn sentinel_rosetta.presentation.controller:app            # HTTP API on :8000
streamlit run src/sentinel_rosetta/presentation/ui/app.py       # needs the API; SENTINEL_API_BASE_URL overrides the address
```

The service sends the text to the model unchanged. A military term appears in the output only if the weights learned it (`ADR-0010` in `docs/DecisionRecord.md`); the original Opus-MT weights often translate such terms differently from the wording of the training data, so fine-tune and install the result (below).

## Models

| Direction | Model | License |
| --- | --- | --- |
| en → zh | `Helsinki-NLP/opus-mt-en-zh` | Apache-2.0 |
| zh → en | `Helsinki-NLP/opus-mt-zh-en` | CC-BY-4.0 |

The models were trained on the OPUS parallel corpus with the Marian NMT framework. `scripts/download_models.py` converts them without retraining. The licenses above describe the original models; a fine-tuned checkpoint is a derivative of them.

## Data

- `data/llm_generated/<source>_to_<target>/llm_generated.jsonl`: the training sentence pairs, generated by an LLM and not human-reviewed.
- `data/llm_reference/` (local only, not in the repository): the reference glossaries behind the sentence pairs. The optional hold-out evaluation (`--holdout-fraction`) reads `data/llm_reference/glossary_en_to_zh.json`, a JSON object with an `entries` list whose items have `abbreviation` (string or null), `full_name` and `zh`. Without the file the command stops before training with `file not found`.

The sentence pairs were generated from the publications listed under [References](#references).

## Fine-tuning

A teacher LLM writes pairs into `data/llm_generated/<source>_to_<target>/`; `validate_generated_records_cli` checks the field format; `finetune_cli` adjusts one direction; the checkpoint is converted and installed. Design: [`docs/DesignDocument_Finetune.md`](docs/DesignDocument_Finetune.md).

One-time setup on the training machine (about 312 MB per direction):

```bash
pip install torch accelerate
python -c "from huggingface_hub import snapshot_download; snapshot_download('Helsinki-NLP/opus-mt-en-zh', local_dir='models/hf/opus-mt-en-zh', allow_patterns=['*.json', '*.spm', 'pytorch_model.bin'])"
```

Use `Helsinki-NLP/opus-mt-zh-en` and `models/hf/opus-mt-zh-en` for the other direction.

```bash
# Check every *.jsonl file in each direction folder; prints "checked <n> records"
python -m sentinel_rosetta.presentation.validate_generated_records_cli

# Fine-tune en -> zh on every record; writes models/finetuned/opus-mt-en-zh/
python -m sentinel_rosetta.presentation.finetune_cli -s en -t zh

# Optional: hold out 25% of the records and compare the original and fine-tuned checkpoints
python -m sentinel_rosetta.presentation.finetune_cli -s en -t zh --holdout-fraction 0.25 --output-dir models/finetuned/opus-mt-en-zh-holdout
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--epochs`, `--batch-size`, `--learning-rate` | 3, 8, 5e-5 | Training settings |
| `--holdout-fraction` | 0 | Share of records held out for evaluation; adds chrF and glossary-term hit lines and needs the local glossary (`ADR-0008`, `ADR-0012` in `docs/DecisionRecord.md`) |
| `--base-model-dir` | `models/hf/opus-mt-<s>-<t>` | Original checkpoint |
| `--output-dir` | `models/finetuned/opus-mt-<s>-<t>` | Must be absent or empty |

The command prints `fine-tuned <n> pairs, train_loss=<x>, saved to <dir>`; progress goes to stderr. The `zh_to_en/` folder holds a small pilot set, far too few pairs for a useful `zh → en` model.

### Install a fine-tuned checkpoint

The service reads `models/opus-mt-<pair>-ct2/` and the tokenizer in `models/opus-mt-<pair>/`. A fine-tuned checkpoint keeps the tokenizer files unchanged, so only the CTranslate2 weights are replaced. Convert into a staging directory, then swap:

```bash
python -c "from ctranslate2.converters import TransformersConverter; TransformersConverter('models/finetuned/opus-mt-en-zh').convert('models/opus-mt-en-zh-ct2.staging', quantization='int8')"
rm -rf models/opus-mt-en-zh-ct2 && mv models/opus-mt-en-zh-ct2.staging models/opus-mt-en-zh-ct2
```

Replace the checkpoint path to install another one; use the `opus-mt-zh-en` names for the other direction. Converting `models/hf/opus-mt-en-zh` the same way restores the original weights. The service loads both directions at startup and fails if either `-ct2` directory is missing, and the API server reads the weights once, so restart it after a swap.

## Known Limitations

- One-word inputs (for example `Hello`) can come back repeated (`你好 你好 你好`). This is Opus-MT beam-search behaviour; `no_repeat_ngram_size=1` removes it but also drops legitimate repetition in longer sentences, so it is not applied.
- Input longer than 512 tokens after tokenization is rejected: HTTP status 422, CLI exit code 1.
